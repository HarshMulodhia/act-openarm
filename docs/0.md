# Architecture and Project Structure

## Objective

Use ACT as the policy model for OpenArm tasks in Isaac Lab while preserving clean boundaries between upstream code and local integration code.

## Actual Workspace Layout

```text
/workspace/
  act/                   # ACT upstream repository (tonyzhaozh/act)
  isaaclab/              # Isaac Lab framework (upstream)
  openarm/               # OpenArm hardware/software meta repository (upstream)
  openarm_act_project/   # ACT integration layer (owned project)
  openarm_isaac_lab/     # OpenArm Isaac Lab extension (upstream)
  tree.log               # Workspace directory listing
```

## Integration Layer Layout (`openarm_act_project/`)

```text
openarm_act_project/
  configs/
    act_openarm_reach.yaml   # Reach task training configuration
  data/
    demos_hdf5/              # Demonstrations collected in simulation
  checkpoints/
    openarm_reach_act/       # Reach task model checkpoints
  scripts/
    collect_openarm_demos.py
    train_act_openarm.py
    eval_act_openarm.py
    deploy_act_openarm.py
  src/openarm_act/
    __init__.py
    datasets/
      openarm_isaac_dataset.py   # Isaac-to-ACT dataset adapter
    envs/
      openarm_isaac_env.py       # Isaac environment wrapper
    policies/
      act_openarm_policy.py      # ACT policy wrapper for runtime inference
    utils/
      io_utils.py                # HDF5 and file I/O helpers
      viz_utils.py               # Visualization helpers
```

## Design Principles

1. Keep upstream repositories unmodified whenever possible.
2. Keep project-specific logic isolated in `openarm_act_project/`.
3. Prefer configuration-driven scripts over hardcoded paths and values.
4. Ensure dataset schema, training inputs, and deployment inputs stay consistent.
5. Track reproducibility inputs: dataset version, config, checkpoint, and code commit.
