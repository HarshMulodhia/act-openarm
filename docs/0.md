# Architecture and Project Structure

## Objective

Use ACT as the policy model for OpenArm tasks in Isaac Lab while preserving clean boundaries between upstream code and local integration code.

## Recommended Workspace Layout

```text
~/workspace/
  isaac-lab/             # Isaac Lab framework (upstream)
  openarm/               # OpenArm meta repository (upstream)
  openarm_isaaclab/      # OpenArm Isaac Lab extension (upstream)
  act/                   # ACT repository (upstream)
  openarm_act_project/   # Integration layer (owned project)
```

## Integration Layer Layout

```text
openarm_act_project/
  configs/               # Task and training configuration
  data/demos_hdf5/       # Demonstrations collected in simulation
  checkpoints/           # Model checkpoints
  scripts/               # Collection, training, evaluation, deployment entry points
  src/openarm_act/
    datasets/            # Isaac-to-ACT dataset adapters
    envs/                # Isaac environment wrappers
    policies/            # ACT policy wrappers for runtime inference
    utils/               # Shared I/O and visualization helpers
```

## Design Principles

1. Keep upstream repositories unmodified whenever possible.
2. Keep project-specific logic isolated in one integration package.
3. Prefer configuration-driven scripts over hardcoded paths and values.
4. Ensure dataset schema, training inputs, and deployment inputs stay consistent.
5. Track reproducibility inputs: dataset version, config, checkpoint, and code commit.
