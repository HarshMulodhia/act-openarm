## 1. Final Project Layout (Code Structure)

Inside the Brev Isaac Launchable VM, use a single `~/workspace` folder to keep upstream repos separate from your glue code:

```text
~/workspace/
  isaac-lab/                     # From isaac-sim/isaac-launchable (preinstalled)
  openarm/                       # github.com/enactic/openarm
  openarm_isaaclab/              # OpenArm Isaac Lab tasks repo (extension)
  act/                           # github.com/tonyzhaozh/act
  openarm_act_project/           # Your project-level code
    configs/
      act_openarm_reach.yaml     # Task + model hyperparams
    data/
      demos_hdf5/                # HDF5 demos recorded in Isaac Lab
    checkpoints/
      openarm_reach_act/         # Trained ACT weights
    src/
      openarm_act/
        __init__.py
        datasets/
          openarm_isaac_dataset.py
        envs/
          openarm_isaac_env.py
        policies/
          act_openarm_policy.py
        utils/
          io_utils.py
          viz_utils.py
    scripts/
      collect_openarm_demos.py   # Isaac Lab demo recorder for OpenArm
      train_act_openarm.py       # ACT training entrypoint
      eval_act_openarm.py        # Eval rollouts in Isaac Lab
      deploy_act_openarm.py      # Live policy deployment in Isaac Sim
```

Roles:

- `isaac-lab/`: simulation and robot-learning core (PPO, imitation, task registration).[^2][^3]
- `openarm_isaaclab/`: defines `Isaac-*-OpenArm-*` tasks and registers them as Isaac Lab environments.[^4][^5]
- `act/`: original ACT implementation; your code imports `imitate_episodes.py`, `policy.py`, and `detr/` without modifying them.[^6]
- `openarm_act_project/`: your integration layer—dataset adapters + Isaac-Lab env wrappers + ACT wrappers and scripts.

## 2. Spin Up Isaac Launchable on Brev

1. On Brev, pick the official Isaac Launchable that uses [`isaac-sim/isaac-launchable`](https://github.com/isaac-sim/isaac-launchable).[^7][^8]
2. Click **Deploy Launchable** and wait until status is running and setup is complete.[^7]
3. Open port `80` in your browser → VS Code Server (default password `password`, change it).[^7]
4. Confirm `isaac-lab/` exists in the workspace from the Launchable template.[^7]

If you ever need a custom Launchable:

- Use this setup script in Brev’s “Create Launchable” flow:

```bash
#!/bin/bash
git clone https://github.com/isaac-sim/isaac-launchable
cd isaac-launchable/isaac-lab
docker compose up -d
```

- Expose ports `80`, `1024`, `47998`, `49100` for VS Code + viewer.[^7]

## 5. Data Collection for ACT with OpenArm in Isaac Lab

### 5.1. What ACT needs

ACT expects each episode to be a sequence of:

- RGB images: `images[t]` (one or more cameras).
- Proprio: `qpos[t]` (joint positions; optionally `qvel[t]`).
- Actions: `actions[t]` (typically joint position targets or deltas).[^10][^6]

Store in an HDF5 structure close to existing ACT/LeRobot conventions:

```text
/episode_000/
  observations/images/cam_main   # uint8 [T, H, W, 3]
  observations/qpos              # float32 [T, n_joints]
  actions/qpos_target            # float32 [T, n_joints]
  meta/success                   # bool
```

This mirrors how ACT and LeRobot structure ALOHA datasets for ACT.[^11][^12]

### 5.2. `collect_openarm_demos.py` (concept)

In `openarm_act_project/scripts/collect_openarm_demos.py`:

1. Initialize Isaac Lab and the OpenArm task, e.g. `Isaac-Reach-OpenArm-v0`.[^5][^4]
2. Create one or more cameras in the stage (e.g., overhead + wrist camera).
3. Each sim step:
    - Read images from cameras.
    - Read current OpenArm joint states.
    - Apply teleop or scripted actions.
    - Append to an episode buffer.
4. At episode end:
    - Save buffers to an HDF5 file under `data/demos_hdf5/episode_xxx.h5`.

Run in viewer mode for debugging:

```bash
cd ~/workspace/openarm_act_project/scripts
python collect_openarm_demos.py \
  --task Isaac-Reach-OpenArm-v0 \
  --output_dir ../data/demos_hdf5 \
  --kit_args="--no-window --enable omni.kit.livestream.webrtc"
```

After it’s stable, you can drop the viewer and run headless to batch-generate demos.

## 6. Wiring the ACT Repo to Use Isaac Lab Data

### 6.1. Install ACT dependencies

From `~/workspace/act` (inside the Launchable’s Python env):

```bash
cd ~/workspace/act
pip install torchvision torch pyquaternion pyyaml rospkg pexpect \
            mujoco==2.3.7 dm_control==1.0.14 opencv-python \
            matplotlib einops packaging h5py ipython
cd detr && pip install -e .
```

Adapt versions if needed to be consistent with the Isaac Lab environment.[^6][^2]

### 6.2. Dataset adapter: `openarm_isaac_dataset.py`

In `openarm_act_project/src/openarm_act/datasets/openarm_isaac_dataset.py`, implement e.g.:

- A PyTorch Dataset that:
    - Enumerates episodes in `data/demos_hdf5/`.
    - Loads images, `qpos`, and `qpos_target`.
    - Produces sequences windows of length `T_obs` with action chunks of length `T_chunk` as ACT expects.

Keep its output as close as possible to what `imitate_episodes.py` expects for the ALOHA datasets.[^6]

### 6.3. Training entry script: `train_act_openarm.py`

In `openarm_act_project/scripts/train_act_openarm.py`:

- Parse a config YAML like `configs/act_openarm_reach.yaml` for:
    - Dataset path.
    - Chunk size, hidden dim, etc.
    - Camera keys, joint count.

Use ACT’s training loop but inject your dataset:

```python
from openarm_act.datasets.openarm_isaac_dataset import OpenArmIsaacDataset
from act.imitate_episodes import train_act  # or similar helper from ACT

def main(cfg):
    dataset = OpenArmIsaacDataset(
        root_dir=cfg["data"]["root_dir"],
        camera_key=cfg["data"]["camera_key"],
        qpos_key=cfg["data"]["qpos_key"],
        action_key=cfg["data"]["action_key"],
    )

    train_act(
        dataset=dataset,
        ckpt_dir=cfg["train"]["ckpt_dir"],
        policy_class="ACT",
        kl_weight=cfg["train"]["kl_weight"],
        chunk_size=cfg["train"]["chunk_size"],
        hidden_dim=cfg["model"]["hidden_dim"],
        batch_size=cfg["train"]["batch_size"],
        dim_feedforward=cfg["model"]["dim_feedforward"],
        num_epochs=cfg["train"]["num_epochs"],
        lr=cfg["train"]["lr"],
        seed=cfg["train"]["seed"],
    )

if __name__ == "__main__":
    # load YAML and call main()
    ...
```

This mirrors the official ACT command but lets you fully control OpenArm-specific dataset loading via your adapter.[^6]

Run training:

```bash
cd ~/workspace/openarm_act_project/scripts
python train_act_openarm.py \
  --config ../configs/act_openarm_reach.yaml
```

Apply ACT’s tuning guidance: if behavior is jerky or pauses, keep training beyond loss plateau; success and smoothness often improve later.[^10][^6]

## 7. Using Hugging Face (Optional but Recommended)

Two useful integrations:

- **Datasets**: Upload `data/demos_hdf5` as a HF dataset (similar to `lerobot/aloha_sim_insertion_human`) so you can version and share your Isaac/OpenArm demos.[^13][^11]
- **Models**: Upload ACT checkpoints as a HF model with a model card documenting:
    - Environment (`Isaac-Reach-OpenArm-v0`).
    - Dataset (OpenArm Isaac Lab demos).
    - Hyperparameters (chunk size, hidden dim, number of epochs, etc.).[^12][^11]

This makes future retraining and benchmarking easier.

## 8. Deploying the Trained ACT Policy in Isaac Sim

### 8.1. Policy wrapper: `act_openarm_policy.py`

In `openarm_act_project/src/openarm_act/policies/act_openarm_policy.py`:

- Load weights from `checkpoints/openarm_reach_act/`.
- Maintain an internal buffer of last `T_obs` frames and joint states.
- When a new chunk is needed:
    - Call the ACT policy (`act.policy.Policy` or similar from `policy.py`) with the observation history.
    - Receive a chunk of future joint targets and cache them.[^6]
- Each Isaac Lab step:
    - Pop the next action from the chunk.
    - If chunk exhausted, query ACT again with the new observation window.


### 8.2. Deployment script: `deploy_act_openarm.py`

This script should:

1. Create the OpenArm Isaac Lab environment (same task used for data collection).
2. Instantiate `ACTOpenArmPolicy` with the checkpoint path.
3. Run a loop:
    - Step the simulation.
    - Get camera images and joint states.
    - Feed into ACT policy wrapper.
    - Apply output joint targets to OpenArm articulation handles.
4. Optionally export video of episodes and log success metrics.

To watch in real time:

```bash
python deploy_act_openarm.py \
  --task Isaac-Reach-OpenArm-v0 \
  --checkpoint ../checkpoints/openarm_reach_act/best.pt \
  --kit_args="--no-window --enable omni.kit.livestream.webrtc"
```

This will stream Isaac Sim at `/viewer`, so you can visually inspect performance.[^2][^7]

## 9. How This Maps Back to Each Repo

- **`enactic/openarm`**: Provides documentation, ROS 2 integration, and URDF/xacro description; you rely on `openarm_isaaclab` for Isaac environments and can later use `openarm_ros2` to bring the trained ACT policy to real hardware.[^14][^15]
- **`openarm_isaaclab`**: Plugs OpenArm into Isaac Lab as tasks; you don’t alter it, just import its tasks and use its configs when building your demo-collection environment.[^5][^4]
- **`tonyzhaozh/act`**: Supplies ACT model code and training loop; you add a dataset adapter and training wrapper in your project but keep their repo clean for easier updates.[^6]
- **`isaac-sim/isaac-launchable`**: Wraps everything in a Brev-friendly Docker setup with VS Code + Isaac Sim + Isaac Lab streaming; you just drop your repos and scripts into its environment and follow its guidance for running scripts and viewer.[^8][^7]
